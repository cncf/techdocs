## Description

Audience: First-time contributors.

Type: Process / Community.

At assessment time, zero open issues carry the `good first issue` label in any
of `hivecommons/docs`, `hivecommons/hive`, or `hivecommons.github.io`, even
though the label and its supporting onboarding documentation exist and are
actively referenced. File the CLI reference landing page, the two
governance-pointer issues, and the accessibility-scan issue in this backlog with
`good first issue` and `documentation` labels (the accessibility-scan issue only
once it states the scanning tool and a clear pass/fail recording step as its
completion criteria) to give new contributors something to claim immediately. Do
not apply `good first issue` to the code-ownership reconciliation or the API
route/doc drift-check issues: choosing approvers is a maintainer decision, and
extracting Go routes and wiring a CI check requires specialist context a
first-time contributor is unlikely to have.

This issue tracks recommended changes resulting from an analysis of the Hive
Commons documentation requested in [cncf/techdocs#395][issue-395].
